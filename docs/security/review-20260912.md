## Deployment and API compatibility

### Network MCP is a single-operator authenticated service

Both HTTP and HTTPS now require an operator-provided `CODANNA_MCP_TOKEN` with
32–512 ASCII bearer-token characters. Generate a random secret, do not use a
sample token, commit it, print it in logs, or share it with an untrusted workspace.
Configure clients to send `Authorization: Bearer <secret>` on MCP requests.
Use a secret manager or an untracked environment file with restricted access.

For local setup, a shell can generate the secret without printing it:

```sh
export CODANNA_MCP_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
# Launch the existing HTTP/HTTPS serve command from this environment.
# Separately configure the same secret in the authorized client's private settings.
```

Plain HTTP can bind only to a loopback IP. Non-loopback service requires HTTPS.
The token is checked on both transports; TLS is not treated as client identity.
Only `/health` remains unauthenticated. The placeholder OAuth authorization,
registration, token, and discovery endpoints are removed rather than repaired
into a pretend authorization server. OAuth-only clients will need a proper
external authorization adapter or a future standards-compliant implementation.

This is **not** multi-user identity, per-workspace ACLs, or OAuth scope enforcement.
A token holder is trusted to use the configured index and its mutations. Use
separate processes/indexes/secrets for separate trust domains. Do not expose a
shared installation to mutually untrusted tenants.

Stdio does not require a network token and is unchanged at that boundary.
The optional, unpinned Context7 `npx` entry is removed from `.mcp_stdio.json`;
users needing that separate tool should install and audit an exact version under
their own lockfile, rather than restoring a mutable automatic download.

### Files, state, and public Rust APIs

Stop every older Codanna server using an index before upgrading. The serve lock
now uses an OS-held file lock; its on-disk file intentionally remains after exit.
Do not unlink an active lock file to force a second server to start.

Invalid/unreadable registry and index metadata now cause errors rather than being
silently replaced. Preserve the file, diagnose the error, and perform explicit
recovery. This batch does not implement a concurrent registry transaction manager.

Plugin clones containing any symlink or special file are rejected, including
internal symlinks. This is intentionally stricter than copying a dereferenced
plugin tree. Existing plugins relying on symlinks must ship regular files.

Search requests accept limits from 1 to 1000; impact depth is 1 to 10. Invalid
parameters return errors, not silent clamping. Internal full-index enumeration
is not capped at 1000; it bounds allocation by actual indexed document count.

The crate-root `StorageError`/`StorageResult` now refer to the active storage API.
The older types remain available as `LegacyStorageError`/`LegacyStorageResult`
and under `error`. Consumers matching old root variants must update their imports.
`CompactSymbol.file_id` is now `u32`; the structure remains 32 bytes, but callers
must not assume the old field offsets are a stable binary persistence format.

`Chunker::chunk` accepts `ValidatedChunkingConfig`. External/Serde settings remain
`ChunkingConfig`; convert with `ValidatedChunkingConfig::try_from(config)` after
merging collection overrides. Invalid settings are rejected before collection
mutation. The existing validation contract requires `overlap < min < max`.

`WriteStage::write` now returns a `StorageResult<WriteStats>`; callers must handle
errors. Its accepted-write count is not a durability receipt until commit/flush
succeeds. Phase two no longer returns successful resolution stats after one of
these writes fails. Already committed work is not rolled back across a failed
multi-batch operation.

Profile removal preserves the lock entry when a tracked file cannot be removed.
Some earlier files may already be deleted; retry is supported. Team sync attempts
remaining profiles but returns an error containing failed entries.

### Visualization compatibility

Repository data is encoded separately for HTML and JavaScript contexts. Generated
pages receive a restrictive CSP, and executable paths/arguments no longer go
through a shell. On Windows, browser URLs are printed for manual opening instead
of invoking the `cmd.exe` `start` builtin.

The Node security suite was exercised with Node 22.16.0. Browser rendering,
accessibility, and every older Node/Codanna version are not certified by that
suite. Do not interpret injection-test success as a complete interactive UI test.

## Continuation: correctness and authoritative regression coverage

Continuation base: PR #23 head `0d0a8f5e5678744ed7fd1764f70f537c2e331a07`.
Source commit: `a8d0088b611e4ce86267c8d897e2ab71985248bf`.

The previous Quick Check/Full Test jobs stopped at Clippy, not at failing executed
tests: std `File::try_lock` exceeded the declared 1.85 lint minimum, and three
new fixture initializers violated strict Clippy rules. The serve lock now uses
`fs4` 0.13.1 (already present transitively in the lockfile), preserving the
lifetime-lock protocol rather than raising the lint minimum or ignoring the lint.
This is not proof that every pinned dependency builds on Rust 1.85; validation
uses the current stable compiler, and the existing dependency MSRV remains a
separate compatibility question.

Additional API migrations:

- `ParserFactory::create_behavior_from_registry` now returns `IndexResult`.
  `ContextStage` behavior snapshots/context/inheritance construction are fallible
  too. Propagate the error instead of substituting another language.
- `FileWalker::walk` and `walk_dirs` yield `IndexResult<PathBuf>`; `count_files`
  and facade discovery helpers return results. Consume the full inventory before
  claiming completeness or imposing an output count limit. Watch discovery errors
  are explicit; this does not make the watcher a transactional indexing actor.
- `TypeScriptBehavior::with_resolution_dir` takes an explicit `.codanna`
  directory. Use an absolute directory for independent workspaces. `new` captures
  the process workspace once, rather than retargeting an existing instance when
  process CWD changes. Clones share one instance's TTL cache; separate instances
  do not share alias rules.
- `SemanticVectorStorage::save_batch_borrowed` is additive; the existing owned
  `save_batch` delegates to it. Borrowed payloads do not change the on-disk format
  or provide upsert/tombstone deltas. Storage is dropped before file publication.

Grammar audit inputs are now mandatory. Lua explicitly uses its parser crate's
embedded node metadata because this repository does not contain a Lua grammar JSON
file. That source is declared in the audit config, not chosen as a silent fallback.
The old ignored workspace-dependent alias example is superseded by the active
isolated pipeline fixture.

The replacement CLI tests also exposed a production mismatch between JSON
`exit_code` and the actual process outcome. Retrieve envelopes now retain the
existing retrieve process vocabulary (not found = 3; invalid query = 1), while
MCP retains its independent 1/2 vocabulary. Projection errors still exit 2.
The fixture checks both interfaces to prevent a global envelope change from
breaking MCP clients.

The regression gate now also runs filesystem/context tests, both TypeScript alias
modules, actual CLI contracts, nonempty parse-command checks, language grammar
audits, cache completeness, and seven Node security/runtime checks. Independent
suites all finish to expose multiple failures in one run, but any failed or empty
Rust filter, or a failed Node suite, makes the final command fail.
