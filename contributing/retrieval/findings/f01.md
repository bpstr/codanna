# F01: Track semantic representation and vector alignment

Status: Implementation and focused fixtures complete; final repository gates and review pending.

`find_symbol` now exposes per-definition semantic diagnostics in MCP structured content/text and CLI JSON metadata. Each returned definition carries its ID, path, name, configured eligibility, recorded source-policy compatibility, embedding identity digest, numeric-ID vector membership and physical vector count. Diagnostics follow pagination; an unknown definition returns no rows. Metadata-only, disabled and unavailable readers report unknown membership rather than infer it from aggregate counts. Aggregate orphan-vector diagnostics remain available through `get_index_info`.

The persistence format does not record the code generation or source hash that produced each vector. Accordingly, every definition reports `vector_code_generation: null`, `generation_alignment: unknown_untracked` and `freshness: unknown`, including definitions with vectors and matching policies. This completes the F01 diagnostic boundary; verifiable source provenance and atomic refresh belong to F04/PR76. Numeric-ID membership is not proof that a vector describes the current definition.

## Executed deterministic comparison

The same synthetic TypeScript source is parsed under DocComment and SymbolBodyV2. Prepared two-dimensional vectors and the same query exercise persistence and retrieval; no embedding model is used. The fixture includes an oversized documented function, an undocumented callable and an unrelated function with identical documentation.

| Representation | Parent symbols | Physical vectors | Persisted bytes after save/reopen |
| --- | ---: | ---: | ---: |
| DocComment | 2 | 2 | 666 |
| SymbolBodyV2 | 3 | 10 | 2,623 |

Body segments collapse to the expected two matching parent IDs, including the undocumented function; the unrelated behavior is excluded. The prepared comment vectors produce no hits at the same query floor. These outcomes test a deliberately assigned fixture oracle, not model quality, relevance improvement, latency or production readiness. Stored byte counts are this small fixture's measurements, not a general storage forecast.

The oversized function reaches eight segments and omits source beyond the retained bound. Source fragments remain within 16 KiB per symbol, with separately bounded identity headers; retained headers and fragments together stay within the 1 MiB file budget. Reopened queries leave persisted byte counts unchanged. DocComment and model defaults, existing source-policy identities and active indexes remain unchanged; diagnostics never rebuild or contact a provider.
