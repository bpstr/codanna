# F09: Measure document segment amplification

Status: Prepared-vector measurement executed; regression fixture passed.

The repeated-update fixture uses one Markdown document and prepared two-dimensional vectors in a temporary index. Every changed revision must process one file and create nonzero chunks and live vectors. After each revision, an unchanged-input control must skip the file, create or remove no chunks, and retain physical/live vector and segment counts.

All revisions reported zero unembedded chunks and zero provider requests. The third revision exercised existing automatic compaction. The regression asserts consistency and meaningful updates without prescribing these exact counts as a permanent compaction policy.

The first execution failed because the draft fixture combined a one-character minimum chunk size with the default 100-character overlap. Setting the fixture overlap to zero corrected its configuration. The failed receipt is preserved with the session validation logs.

These results describe this small prepared-data fixture only. They do not establish production storage amplification, scale, reclaimed disk bytes or provider quality. No active user index was opened or changed, and no compaction policy was modified. Tests use prepared data without provider credentials or paid inference.
