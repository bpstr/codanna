# F04: Track source freshness and publication provenance

Status: Implemented and exercised with deterministic local fixtures.

Semantic vector persistence now records each vector's indexed source SHA-256 and the durable Tantivy commit opstamp. The version-5 journal binds provenance to checkpoints and deltas under the same semantic manifest, validates hashes on save and reopen, and removes provenance with vector tombstones. Legacy or partial indexes remain explicit as `unknown_untracked`.

`find_symbol` reports the indexed, currently observed and vector-producing source hashes; reader and vector generations; source freshness; generation alignment; and combined freshness. Current-source reads reject symlinks, are limited to 16 MiB per unique file and 32 MiB per request, and never mutate either index. Missing, unreadable, oversized and untracked sources remain explicit.

The F04 before/after Go fixture exercises a matching source, an edit before publication, a missing source, refreshed code/vector publication, checkpoint reopen and delta reopen. A prepared-cache pipeline test verifies that collected file hashes reach vector provenance using a loopback mock transport. No external embedding request is made. Provider request count is zero.

Semantic search mode is unchanged. Code and semantic directories are still published separately; this change records their relationship and exposes stale or unknown alignment instead of claiming cross-directory atomicity. Aggregate generation alignment is reported only when every stored vector has the same recorded generation.

Focused provenance, semantic journal, collector and embedding-stage tests pass locally. Repository-wide gate and review results are recorded in PR76 before merge. No paid inference, provider credentials, subscription proxy, automatic recording, private source publication or active user index mutation occurred.
