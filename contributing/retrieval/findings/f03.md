# F03: Track lazy component composition

Status: Implemented and executed locally.

TypeScript and JavaScript indexing now recognizes a bounded React `lazy` composition shape: a zero-argument factory, a literal relative dynamic import, and a single `then` projection of one named export into `default`. The emitted dependency is a `Uses` edge from the JSX owner to the exact module export. It is never emitted as an immediate `Calls` edge.

Resolution uses the existing module export resolver and fails closed for missing, ambiguous, external and type-only targets. The parser also claims rejected lazy JSX sites so ordinary same-name fallback cannot connect a namesake declaration.

The deterministic integration test covers cached and uncached imports, save/reopen persistence, forward and reverse relationships, and static import/call compatibility. Negative controls cover shadowed or reassigned bindings, a reassigned cache or wrapper, a shadowed wrapper, computed projections, missing and type-only exports, external packages, duplicate or spread object properties, and block callbacks.

Executed with provider credential variables removed:

- `cargo test --test lazy_component_composition`: 1 passed, 0 failed.
- `cargo test --lib --no-run`: compiled successfully.

Provider requests: 0. The test uses only checked-in synthetic sources and a local temporary index. The original failing test evidence is retained in the local execution artifact for this change.

The recognizer intentionally excludes general promise chains, nonliteral or package imports, block callbacks, computed member access and object projections with additional properties. Those forms remain unresolved rather than falling back to a same-name symbol.
