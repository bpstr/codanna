# F03: Track lazy component composition

Status: Implemented and executed locally.

TypeScript, TSX, JavaScript and JSX indexing now recognizes a bounded React `lazy` composition shape: a module-scope immutable component, a zero-argument factory, a literal relative dynamic import, and a single `then` projection of one named export into `default`. The emitted dependency is a `Uses` edge from the JSX owner to the exact module export. It is never emitted as an immediate `Calls` edge.

Resolution uses the existing module export resolver and fails closed for missing, ambiguous, external and type-only targets. The parser also claims rejected lazy JSX sites so ordinary same-name fallback cannot connect a namesake declaration.

The deterministic integration test covers cached and uncached imports, TSX and JSX parsing, save/reopen persistence, forward and reverse relationships, and static import/call compatibility. Negative controls cover nested declarations, local function and class shadows, shadowed or reassigned bindings, initialized or reassigned caches, a reassigned or shadowed wrapper, computed projections, missing and type-only exports, external packages, duplicate or spread object properties, block callbacks, and incomplete depth-bounded validation.

Executed with provider credential variables removed:

- `cargo test --test lazy_component_composition`: 2 passed, 0 failed.
- `cargo test --lib --no-run`: compiled successfully.

Provider requests: 0. The test uses only checked-in synthetic sources and a local temporary index. The original failing test evidence is retained in the local execution artifact for this change.

The recognizer intentionally excludes general promise chains, nonliteral or package imports, block callbacks, computed member access and object projections with additional properties. Those forms remain unresolved rather than falling back to a same-name symbol.
