# F11: Track document corpus drift

Status: Complete diagnostic implementation, verified with deterministic fixtures.

`documents drift` and the typed `document_drift` MCP tool compare committed source hashes with configured collection files. The read-only loader uses Tantivy's committed generation pointer and never invokes the mutable store constructor. Collection discovery applies globs, `.codannaignore`, managed-index exclusions and collection ownership. Scoped MCP inspection validates persisted metadata and source provenance against the workspace boundary.

Reports include generation identity, indexed/current hashes, source statuses and effective file, byte and discovery-entry limits. Raw entries are counted before ignore filtering, including ignored files. Depth and ignore-policy reads also have limits. Special files and symlink replacements cannot block a source read. Unsupported or unreadable sources carry no current hash; truncated reports cannot certify freshness.

Deterministic fixtures cover changed, missing, new and unchanged sources, non-mutation of persistence even when its compatibility mirror is absent, file/byte/discovery limits, ignored files, symlink roots, cross-collection ownership, invalid UTF-8, oversized ignore policies, invalid requests, model-free CLI access, structured MCP responses and workspace-boundary refusal. A bounded subprocess regression replaces an indexed source with a FIFO. No paid inference, provider credentials or active user-corpus mutation is involved.

All 12 focused drift tests passed. Initial failures exposed missing entry points, a schema import and workspace path canonicalization; the failed receipts are retained alongside the passing run.

Concurrent publication may invalidate a metadata read; callers should retry a reported error. This diagnostic does not refresh the index or claim an atomic snapshot of the live filesystem. Existing generations and historical failed test receipts are preserved.
